Regras de Visibilidade (Lógica de Backend)
Ao criar suas queries no banco de dados, você deve aplicar estes filtros:

CanViewAll: Se true, retorna SELECT *.
CanViewTeam: Se true, retorna SELECT * WHERE team_id = user.team_id.
Padrão (Nenhum dos acima): Retorna SELECT * WHERE agent_id = user.id (apenas itens atribuídos ao usuário).

3. Regras de Distribuição de Tickets (Roteamento)
Lógica extraída de functions/assignTicketRoundRobin.js.

Você precisará implementar um "Worker" ou Job que rode a cada X segundos ou via Webhook na criação do ticket.

Algoritmos de Distribuição:

Round Robin (Rodízio):

Mantém uma lista ordenada de agentes (agent_sequence).
Verifica quem foi o último a receber (last_assigned_agent_id).
Entrega para o próximo da lista que esteja Online e Ativo.
Atualiza o ponteiro do último agente.
Least Active (Menor Carga):

Conta quantos tickets com status != resolvido/fechado cada agente da fila tem.
Entrega para o agente com o menor número de tickets abertos.
Regras de Exclusão (Quem NÃO recebe ticket):

Agentes Offline (se a regra consider_online_status for true).
Agentes fora do Horário Comercial (se working_hours_only for true).
Agentes que não pertencem à Fila (queue_ids não bate).
4. Regras de SLA (Service Level Agreement)
Lógica extraída de functions/checkSLAWarnings.js.

Seu backend precisa de um CRON JOB rodando a cada minuto para verificar:

Prazos (Deadlines): Os prazos são calculados baseados na Prioridade do ticket (P1, P2, P3, P4):

Primeira Resposta: Tempo entre created_at e a primeira mensagem do agente.
Resolução: Tempo entre created_at e status resolvido.
Lógica de Pausa:

O cronômetro do SLA PAUSA se o ticket estiver em status definidos em pause_on_status (ex: aguardando_cliente, aguardando_terceiro).
Alertas:

Se faltar X minutos para vencer e ainda não foi resolvido -> Enviar notificação/email para o agente.
Se venceu -> Marcar sla_breached = true e notificar supervisor.
5. Automação de Leads (Sales Automation)
Lógica extraída de functions/checkLeadAutomations.js.

Outro CRON JOB necessário. Ele varre todos os leads ativos e aplica regras "Gatilho -> Ação".

Gatilhos Suportados:

Tempo no Estágio: Se o lead ficar mais de X dias/horas parado no mesmo estágio do funil (stage_duration).
Ações Suportadas:

Mover Lead: Alterar o stage automaticamente (ex: de "Novo" para "Perdido" após 30 dias sem contato).
Criar Tarefa: Gerar uma Activity do tipo task para o vendedor.
Notificar: Criar um alerta no sistema.
Enviar WhatsApp: Disparar mensagem ativa via integração (Wescctech API) substituindo variáveis {{lead_name}}, {{agent_name}}.
Resumo Técnico para Migração (O que criar no Replit)
Tabelas de Enum: Crie tabelas ou const no código para AgentLevels, AgentTypes, TicketPriorities.
Middlewares de Permissão: Crie um middleware no Express que leia o role do usuário e aplique a lógica da seção 1 antes de retornar dados.
Background Jobs (Cron):
JobDistribuição: Roda a cada 10s ou gatilho de novo ticket.
JobSLA: Roda a cada 1 min.
JobAutomaçãoLeads: Roda a cada 1 hora.
Endpoints de Negócio: Além do CRUD, você precisará de endpoints específicos para ações como POST /api/tickets/assign (forçar distribuição) e POST /api/leads/automate (rodar automações manualmente).
